# Product Specification

## 1. Product Name

StarterKit AI

---

## 2. Purpose

StarterKit AI is a reusable frontend foundation for building AI-powered applications.

It provides a standardized user experience and frontend architecture for consuming AI capabilities through an existing backend API Gateway.

The starter kit does not implement AI infrastructure.

---

## 3. Product Boundary

### Frontend Responsibilities

The frontend is responsible for:

* user interface
* authentication experience
* chat experience
* conversation experience
* assistant response rendering
* streaming response rendering when the Gateway supports SSE
* source/citation rendering
* product/document search UI
* summarization UI
* client-side validation
* API communication
* error handling
* responsive experience

### Backend Responsibilities

The existing NestJS API Gateway is responsible for:

* authentication integration
* authorization
* AI orchestration
* Dify integration
* RAG
* LLM integration
* knowledge retrieval
* document processing
* backend business rules

---

## 4. Core User Journey

```text
User opens application
        ↓
Authentication
        ↓
AI Chat
        ↓
User enters question
        ↓
Frontend sends request to API Gateway
        ↓
API Gateway processes request
        ↓
Frontend receives the Gateway response
  (complete JSON by default; SSE only if the Gateway contract supports it)
        ↓
Frontend renders assistant response
        ↓
Frontend renders source information
```

---

## 5. Core Capabilities

### Authentication

Users can:

* authenticate
* access authenticated application
* logout
* receive appropriate unauthorized handling

### AI Chat

Users can:

* enter questions
* submit questions
* receive assistant responses
* receive streaming responses when the Gateway supports SSE
* view assistant responses
* view markdown content
* view code blocks
* view sources
* retry failed requests where supported

### Conversation

Users can:

* create conversations
* continue conversations
* view conversation history
* switch between conversations
* start a new conversation

Actual capabilities depend on the API Gateway contract.

### Source Citation

Users can view supporting information returned by the backend.

The frontend must display source data exactly as provided by the API.

The frontend must never fabricate:

* document name
* page
* section
* relevance
* citation metadata

### Search

The frontend may provide natural-language search experiences backed by the API Gateway.

The frontend does not implement search or retrieval algorithms.

### Summarization

The frontend may display summaries generated by the backend.

The frontend does not generate or modify AI summaries.

---

## 6. Non-Goals

The frontend does NOT implement:

* RAG
* embeddings
* vector search
* document ingestion
* document parsing
* chunking
* LLM orchestration
* prompt engineering infrastructure
* Dify integration
* AI model management
* AI provider credentials
* database access

---

## 7. Reusability Requirement

The starter kit should be usable for multiple AI applications without significant architectural changes.

Business-specific functionality should be implemented as features or configuration rather than modifying generic AI components.
